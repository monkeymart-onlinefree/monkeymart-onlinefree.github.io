Use the Base64 Encode / Decode tool to convert UTF-8 text into Base64-encoded strings or decode Base64 data back into readable text. Enter your input and choose between standard Base64 and Base64URL formats to generate the corresponding output.

What Is the Base64 Encode / Decode Tool?

Base64 Encode / Decode is a text conversion tool that represents data using a 64-character encoding alphabet.

Base64 is commonly used when binary data needs to be represented as text, such as in web applications, APIs, and data exchange formats.

The tool supports standard Base64 and Base64URL encoding. Both formats use the same underlying conversion method but differ in two alphabet characters.

How to Use the Base64 Encode / Decode Tool

Follow these steps to convert your text:

  1. Input: Enter the original text you want to encode or the Base64 string you want to decode.
  2. Conversion: Choose Encode to generate Base64 text or Decode to recover the original text.
  3. Format: Select standard Base64 or Base64URL, depending on the required format.
  4. Output: View the converted result in the output field.

When decoding, use the format that matches the original encoded data.

Formula / Calculation Method

Base64 encoding converts binary data into text by dividing its bits into groups of six. Each six-bit group represents an index in a 64-character alphabet.

The conversion follows the encoding method defined in RFC 4648.

Main Formula

The encoding process follows this relationship:

\[ 3\text{ bytes}\times8\text{ bits}=24\text{ bits} \]
\[ 24\text{ bits}\div6\text{ bits}=4\text{ Base64 characters} \]

Every complete group of three input bytes produces four Base64 characters.

For standard Base64 with padding, the encoded length is:

\[ L=4\times\left\lceil\frac{n}{3}\right\rceil \]

Variables

  • L: Encoded output length in characters.
  • n: Number of input bytes after UTF-8 conversion.
  • 8: Number of bits in one byte.
  • 6: Number of bits represented by each Base64 character.
  • ⌈ ⌉: Ceiling operation, which rounds upward to the nearest whole number.

Standard Base64 Alphabet

Standard Base64 uses the following 64 characters:

ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/

The character = is reserved for padding and is not part of the 64-character data alphabet.

Base64URL Alphabet

Base64URL uses the same conversion process but replaces two characters:

Standard Base64 Base64URL
+ -
/ _

These replacements make the alphabet more suitable for URLs and filenames.

Calculation Sequence

Encoding

  1. Convert the input text into UTF-8 bytes.
  2. Read the bytes in groups of three.
  3. Combine each complete group into 24 bits.
  4. Divide those bits into four six-bit groups.
  5. Convert each six-bit value into its corresponding Base64 character.
  6. Handle any remaining input bytes using zero-filled bits and the applicable padding rules.

Decoding

  1. Read the encoded characters using the selected Base64 alphabet.
  2. Convert each data character into its corresponding six-bit value.
  3. Combine the bit groups to recover the original bytes.
  4. Exclude padding from the recovered data.
  5. Interpret the resulting bytes as UTF-8 text.

Padding Rules

Standard padded Base64 uses = when the final input group contains fewer than three bytes.

Remaining Input Padding
3 bytes None
2 bytes One =
1 byte Two ==

Base64URL also defines = as a padding character, although specifications using Base64URL may permit omitted padding when the data length can be determined.

Worked Example

Encode the text Hi using standard Base64.

Inputs

  • Input text: Hi
  • Conversion: Encode
  • Format: Standard Base64

Step 1: Convert Text into UTF-8 Bytes

Both characters have a one-byte UTF-8 representation.

Character Decimal Value Binary
H 72 01001000
i 105 01101001

Combined binary sequence:

01001000 01101001

Step 2: Divide into Six-Bit Groups

Split the 16 input bits into six-bit groups, adding zero bits to complete the final group.

010010 000110 100100

The corresponding decimal indexes are:

18, 6, 36

Step 3: Convert to Base64 Characters

Using the standard Base64 alphabet:

Decimal Index Base64 Character
18 S
6 G
36 k

Because the input contains two bytes, one = padding character completes the encoded output.

Final Result

Original text: Hi

Base64 output: SGk=

Decoding SGk= using the same format returns Hi.

Understanding Your Results

The output depends on the selected conversion direction.

Encoded Output

When Encode is selected, the result is a Base64 representation of the UTF-8 input data.

For example:

Original Text Base64 Result
Hello SGVsbG8=
Test VGVzdA==
Hello World SGVsbG8gV29ybGQ=

The encoded string represents the original bytes using characters from the selected Base64 alphabet.

Decoded Output

When Decode is selected, the tool converts the encoded data back into bytes and interprets them as UTF-8 text.

The recovered output should match the original text when the input contains valid Base64 representing valid UTF-8 data.

Base64 encoding changes how data is represented. It does not encrypt or secure the underlying information.

Assumptions and Limitations

  • UTF-8 text: The tool is designed to encode and decode text using UTF-8.
  • Binary data: A Base64 string can represent arbitrary binary bytes, which may not produce meaningful readable text when decoded.
  • Encoding format: Standard Base64 and Base64URL use different characters for alphabet positions 62 and 63.
  • Padding: Standard Base64 uses padding when required. Padding conventions can differ between specifications that use Base64URL.
  • Invalid input: Incorrect characters, malformed padding, or unsuitable encoded data may prevent successful decoding.
  • Security: Base64 is an encoding method, not encryption. Encoded information can be decoded without a secret key.

The result depends on the supplied input and the selected encoding format.

Frequently Asked Questions

1. Is Base64 encoding the same as encryption?

No. Base64 converts data into a different text representation. It does not protect confidential information because the original data can be recovered through decoding without a secret key.

2. Can Base64 encode Unicode characters and emojis?

Yes. Unicode text can be converted into UTF-8 bytes before Base64 encoding. Characters outside standard ASCII may occupy multiple bytes, which affects the encoded output.

3. Why does a Base64 string sometimes end with =?

The = character is used for padding when the final input group contains fewer than three bytes. Standard padded Base64 produces output lengths that are multiples of four characters.

4. What is the difference between Base64URL and URL encoding?

Base64URL represents binary data using a URL-safe variation of the Base64 alphabet.

URL encoding, also called percent-encoding, represents certain characters using hexadecimal escape sequences, such as %20 for a space.

These are different conversion methods.

5. Can every Base64 string be converted into readable text?

No. Base64 can represent arbitrary binary information. If the decoded bytes do not form valid UTF-8 text, the result cannot always be displayed meaningfully as readable characters.

6. Does Base64 encoding reduce text size?

No. Standard padded Base64 normally increases the amount of data needed to represent the original bytes. Every complete three-byte input group becomes four encoded characters.

7. Are Base64 characters case-sensitive?

Yes. Uppercase and lowercase letters represent different values in the Base64 alphabet. Changing their capitalization can alter the decoded data.
