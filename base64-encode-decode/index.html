What Is the Base64 Encode / Decode?

This Base64 tool converts UTF-8 text to a Base64 representation or reverses Base64 back into text. Base64 is a binary-to-text encoding standardized by RFC 4648; it is useful for transport and embedding, but it is not encryption.

How to Use the Base64 Encode / Decode

Choose Encode or Decode, select standard Base64 or Base64URL, paste your input, and run the conversion. For Unicode text, the page uses UTF-8 bytes before encoding, avoiding the common browser limitation of applying btoa() directly to non-ASCII characters.

Base64 Encode / Decode Formula

Base64 groups input into 24-bit blocks, then represents those bits as four 6-bit values mapped to a 64-character alphabet. Standard padding uses “=” when the final input block is shorter than three bytes.

Formula Variables

The standard alphabet uses A–Z, a–z, 0–9, +, and /. Base64URL substitutes - and _ for + and /. This page treats decoded text as UTF-8.

Calculation Example

The UTF-8 text “Hello” encodes to “SGVsbG8=”. Decoding that Base64 string returns “Hello”.

Understanding Your Results

The output area shows the converted value and input/output character counts. Copying happens entirely in your browser.

Important Factors

Base64 expands data size because each 3 input bytes normally become 4 Base64 characters. Whitespace, missing padding, and URL-safe alphabets can affect interoperability across systems.

Limitations

This tool is designed for text and UTF-8 data. A Base64 string may represent arbitrary binary bytes that are not valid UTF-8 text; such data cannot always be displayed meaningfully as characters.

Frequently Asked Questions

Is Base64 encryption?

No. Base64 is an encoding that represents binary data using printable characters. It provides no secrecy by itself.

Does this tool support Unicode text?

Yes. Text is converted to UTF-8 bytes before Base64 encoding and UTF-8 bytes are decoded back to text.

What is Base64URL?

RFC 4648 defines a URL- and filename-safe Base64 alphabet that replaces + and / with - and _. Padding may be omitted in contexts where the data length is otherwise known.
