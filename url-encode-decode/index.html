The URL Encode / Decode tool converts URL text between readable text and percent-encoded form. It supports whole-URI and URI-component processing so you can encode or decode complete URLs or individual URL values.

What Is the URL Encode / Decode Tool?

The URL Encode / Decode tool converts characters into or from URL percent-encoding. Percent-encoding represents certain bytes with a percent sign followed by two hexadecimal digits, such as %20 for a space.

The tool is useful when working with URLs, paths, query values, fragments, APIs, redirects, or other web data that may contain spaces, symbols, or Unicode characters.

How to Use the URL Encode / Decode Tool

  1. Enter the text or URL in the Input field.
  2. Use whole-URI mode when processing a complete URL whose structural characters should remain meaningful.
  3. Use URI-component mode when processing an individual value such as a path segment, query value, or fragment value.
  4. Choose whether to encode or decode the input.
  5. Read the converted value in the Output field.

Whole-URI mode follows the browser's encodeURI() and decodeURI() behavior. URI-component mode follows encodeURIComponent() and decodeURIComponent().

Formula / Calculation Method

Main Formula

A percent-encoded byte has this form:

Percent-encoded octet = "%" + two hexadecimal digits

RFC 3986 defines the syntax as:

pct-encoded = "%" HEXDIG HEXDIG

For example:

Space → byte 0x20 → %20

For Unicode text, characters are represented using their UTF-8 bytes before the required bytes are written as %XX sequences.

Browser Functions Used

Whole URI encoding

Output = encodeURI(Input)

Whole URI decoding

Output = decodeURI(Input)

URI component encoding

Output = encodeURIComponent(Input)

URI component decoding

Output = decodeURIComponent(Input)

encodeURI() preserves many characters that are used as URL syntax, while encodeURIComponent() encodes a larger set of characters because the input is treated as one URI component.

Calculation Sequence

For encoding:

  1. Read the input string.
  2. Apply the selected whole-URI or URI-component encoding method.
  3. Represent Unicode text using UTF-8 bytes where encoding is required.
  4. Convert each encoded byte to two hexadecimal digits.
  5. Add % before each hexadecimal byte value.
  6. Return the resulting string.

For decoding:

  1. Read the encoded input.
  2. Identify valid %XX sequences.
  3. Convert the hexadecimal values back to bytes.
  4. Interpret valid multi-byte sequences as UTF-8 characters.
  5. Apply the selected whole-URI or URI-component decoding behavior.
  6. Return the decoded text.

Whole URI vs. URI Component Encoding

Whole-URI encoding preserves structural URL characters such as:

; / ? : @ & = + $ , #

This allows a complete URL to keep its URL structure.

URI-component encoding processes more of these characters because they could otherwise be interpreted as URL delimiters. For example, & in a query value becomes %26 with encodeURIComponent().

Worked Example

Suppose you want to encode this text as a URI component:

Inputs

green tea & coffee

Step 1

The spaces have the hexadecimal byte value 20.

space → %20

Step 2

The ampersand has the byte value 26.

& → %26

Step 3

The letters remain readable while the spaces and ampersand are percent-encoded.

Final Result

green%20tea%20%26%20coffee

Decoding that value with URI-component decoding returns:

green tea & coffee

Understanding Your Results

The Output field contains the converted version of the input.

When encoding, sequences such as %20, %26, and %3F represent encoded byte values. A Unicode character may require several UTF-8 bytes and can therefore produce several consecutive %XX sequences.

When decoding, valid encoded sequences are converted back to their corresponding characters.

The selected mode matters. For example, whole-URI decoding intentionally preserves encoded forms of certain reserved URL characters because decoding them could change the meaning or structure of the URI.

Assumptions and Limitations

This tool follows the browser JavaScript encodeURI(), encodeURIComponent(), decodeURI(), and decodeURIComponent() functions rather than implementing a separate URL-normalization algorithm.

Percent-encoding is not identical to application/x-www-form-urlencoded form encoding. Form-encoded data commonly represents spaces with +, while generic URI percent-encoding normally represents a space as %20. decodeURIComponent() does not automatically treat every + as a space.

Encoding the same value more than once can change the result. For example, the % character is encoded as %25 when it is treated as ordinary data. RFC 3986 warns against repeatedly encoding or decoding the same URI text because this can change its interpretation.

Malformed percent sequences or invalid UTF-8 data can cause URI decoding to fail. For example, a % that is not followed by two hexadecimal digits can produce a URIError in the browser decoding functions.

Because the calculator follows JavaScript browser functions, its escaping behavior should not be treated as a separate strict RFC 3986 normalization routine.

Frequently Asked Questions

What is URL percent-encoding?

Percent-encoding represents a byte with % followed by two hexadecimal digits. For example, a space can be represented as %20.

What is the difference between whole-URI and URI-component mode?

Whole-URI mode is intended for complete URLs and preserves important URL delimiters. URI-component mode encodes more reserved characters and is better suited to individual URL values such as query values or path components.

Why does a space become %20 instead of +?

The browser URI encoding functions use percent-encoding, so a space is encoded as %20. The + convention belongs to form-style URL encoding and is not the same process.

Why is & unchanged in whole-URI mode?

An ampersand can have structural meaning inside a URI. encodeURI() therefore preserves it, while encodeURIComponent() encodes it as %26.

Can the tool encode Unicode characters?

Yes. The browser URI encoding functions represent Unicode characters using UTF-8 and percent-encode the required bytes. A single character may therefore become several %XX sequences.

Why can URL decoding fail?

Decoding can fail when the input contains an incomplete percent sequence, invalid hexadecimal encoding, or a byte sequence that does not represent valid UTF-8 text. Browser decoding functions can report this as a malformed URI sequence.
