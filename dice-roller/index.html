The Dice Roller generates virtual dice results for standard six-sided dice or dice with a custom number of sides. Enter the number of dice and the number of sides to see each roll along with the total, average, minimum, and maximum.

What Is the Dice Roller?

The Dice Roller is a browser-based tool for generating random integer results that simulate rolling dice. It can be used for tabletop games, probability exercises, classroom activities, or any situation where you need one or more random results within a fixed range.

Each die produces a value from 1 to the selected number of sides.

How to Use the Dice Roller

Enter the following values:

Number of dice: The number of virtual dice you want to roll. Use a positive whole number.

Sides on each die: The number of possible values on each die. For example, enter 6 for a standard six-sided die or 20 for a 20-sided die.

Run the roll to generate the individual results and supporting calculations.

Formula / Calculation Method

Main Random-Roll Method

For a die with ss sides, the calculator generates a uniformly distributed integer:

R∈{1,2,3,…,s}R \in \{1,2,3,\ldots,s\}

The calculator uses the browser's crypto.getRandomValues() method to obtain cryptographically strong random values.

It then uses rejection sampling so that mapping the raw random integer to the requested number of sides does not introduce modulo bias.

Let:

  • UU = raw unsigned random integer
  • MM = number of possible values in the raw random integer range
  • ss = number of sides on the die
  • LL = largest multiple of ss that fits within the raw random range

The acceptance limit is:

L=⌊Ms⌋×sL=\left\lfloor\frac{M}{s}\right\rfloor\times s

If:

U≥LU \geq L

the value is discarded and another random value is generated.

For an accepted value:

R=(U mod s)+1R=(U\bmod s)+1

This produces an integer from 1 through ss. Rejection sampling prevents some faces from receiving more possible raw values than others when the underlying random-number range is not exactly divisible by the number of sides.

For a discrete uniform distribution with ss equally likely outcomes, each individual result has probability:

P(R=k)=1sP(R=k)=\frac{1}{s}

for k=1,2,…,sk=1,2,\ldots,s.

Calculation Sequence

  1. Read the number of dice.
  2. Read the number of sides on each die.
  3. Generate a random value with crypto.getRandomValues() for each die.
  4. Reject raw values outside the unbiased acceptance range.
  5. Map each accepted value to an integer from 1 through the selected number of sides.
  6. Store every individual roll.
  7. Add the rolls to calculate the total.
  8. Divide the total by the number of dice to calculate the average.
  9. Find the smallest and largest individual roll.

Total

If the individual dice results are:

R1,R2,…,RnR_1,R_2,\ldots,R_n

the total is:

T=∑i=1nRiT=\sum_{i=1}^{n}R_i

Average

The average roll is:

Average=Tn\text{Average}=\frac{T}{n}

The average may contain a decimal even though every individual die result is a whole number.

Minimum

Minimum=min⁡(R1,R2,…,Rn)\text{Minimum}=\min(R_1,R_2,\ldots,R_n)

This is the lowest individual value rolled.

Maximum

Maximum=max⁡(R1,R2,…,Rn)\text{Maximum}=\max(R_1,R_2,\ldots,R_n)

This is the highest individual value rolled.

Roll Range

The displayed roll range is:

Minimum−Maximum\text{Minimum} - \text{Maximum}

For example, if the smallest result is 2 and the largest is 6, the roll range is 2–6.

Understanding Your Results

Individual rolls show the generated value for each virtual die.

Total is the sum of every die in the current roll.

Average is the total divided by the number of dice. It describes the mean value of that specific set of rolls.

Minimum is the smallest value generated during the roll.

Maximum is the largest value generated during the roll.

A repeated number or a streak of similar numbers does not by itself indicate that the generator is biased. Random sequences can naturally contain duplicates and short patterns.

Assumptions and Limitations

The calculator models dice as discrete uniform random outcomes. For a die with ss sides, the intended probability of each face is 1/s1/s.

The results simulate virtual dice; they do not predict how a physical die will land. Real physical dice can be affected by manufacturing differences, shape, surfaces, throwing conditions, and other physical factors.

crypto.getRandomValues() supplies cryptographically strong random values, but the Web Cryptography specification explains that browsers generally use cryptographically strong pseudorandom-number generators seeded with entropy rather than requiring a physical true-random source.

Rejection sampling is important when the raw integer range cannot be divided evenly by the requested number of sides. It removes values that would otherwise make some modulo results occur slightly more often.

The number of dice and number of sides should be positive whole numbers. Total, minimum, maximum, and individual rolls are integers, while the average can be fractional.

Frequently Asked Questions

Is every side equally likely to be rolled?

The calculator's algorithm is designed to give each value from 1 through the selected number of sides an equal probability. For an ss-sided die, the theoretical probability of each face is 1/s1/s.

Why does the Dice Roller use rejection sampling?

Simply applying the modulo operator to every possible raw random integer can create a small bias when the raw range is not evenly divisible by the number of die sides. Rejection sampling removes the extra portion of the raw range before the modulo operation.

Can I roll dice with a custom number of sides?

Yes. Enter the required value in the Sides on each die input. The algorithm maps accepted random values to integers between 1 and the selected number of sides.

How is the average calculated?

The calculator adds all individual dice results and divides that total by the number of dice:

Average=TotalNumber of Dice\text{Average}=\frac{\text{Total}}{\text{Number of Dice}}
Why did I roll the same number several times?

Independent random rolls can repeat. For example, rolling several 6s in a short sequence is possible and does not automatically mean the generator is unfair.

Is this the same as true physical randomness?

Not exactly. The browser API provides cryptographically strong random values through its random-number system. The Web Cryptography specification does not require browsers to obtain every value directly from a physical random process.

Can this calculator predict a real dice roll?

No. It generates new virtual random results and does not predict the outcome of a physical die.
